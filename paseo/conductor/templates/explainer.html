How the sync engine works

One page, plain words: what happens between a change on one device and the same change on another.

Summary

In short: every change is written locally first, queued, and sent in small batches; the server orders them and fans them out.

The flow

  1. Write locally

    The app saves the change on the device right away, so it never waits on the network.

  2. Queue and batch

    Changes wait in a queue and leave every 2 seconds, or sooner when 50 pile up.

  3. Order on the server

    The server stamps each batch with a sequence number, so every device applies changes in the same order.

  4. Fan out

    Other devices get the batch over a live connection and apply it.

Details

The queue survives restarts because it lives in the local database. A batch that fails is retried with backoff: 

retry delay = min(30 s, 1 s × 2^attempt)

Risks

Two devices editing the same field offline: the later batch wins. Fine for titles, not for counters.
