# Using Skills

Select skills by the requested outcome. Read the closest matching skill when its workflow or tools help; ordinary questions and small edits do not need a skill ceremony.

- Honor an explicitly named skill. Otherwise use the description to distinguish actual task fit from shared keywords.
- Read the selected `SKILL.md` once, then only references needed for the current branch. Do not load the whole catalog.
- Use the host's available skill loader or file reader. Do not assume tools named `Skill` or `TodoWrite` exist.
- Preserve user scope, choices, and existing authorization. A skill does not override explicit user instructions or require brainstorming before an already specified edit.
- Keep essential constraints and completion criteria; adapt optional recipes to the task. Track substantial multi-step work with available planning tools when useful.
- If a referenced tool or skill is unavailable, use an equivalent supported path and disclose any material limitation.

Finish when the requested result is delivered and relevant checks support it. Do not add interviews, reviews, or skill-authoring work merely because another skill mentions them.
